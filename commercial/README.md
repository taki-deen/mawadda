# مَوَدّة | النسخة التجريبية التجارية

تطبيق عربي لحسابين مستقلين يجيبان عن أسئلة 15 محورًا. من «الرئيسية» ابدأ جلسة أو تابع جلسة قائمة. تعرض صفحة «المحاور» تقدّمك، وتفتح صفحة «الطرف الآخر» رابط الدعوة. استخدم «حفظ ومتابعة» أثناء الإجابة، ثم راجع مشاركة المحور قبل المقارنة. يفتح الخادم مقارنة كل محور بعد موافقة الطرفين على مراجعات إجاباتهما الحالية لذلك المحور. يعيد تعديل الإجابة موافقة صاحبها في ذلك المحور إلى حالة الانتظار واعتماد ملاحظة السؤال إلى المراجعة، مع الاحتفاظ بنص الملاحظة.

## التشغيل المحلي

من مجلد `commercial` باستخدام Node.js 22.12 أو أحدث على خط 22.

```sh
npm ci
npm run dev
npm test
npm run check
```

يفتح `npm run dev` المعاينة على `http://127.0.0.1:3001` ويستخدم PostgreSQL مضمّنًا عبر PGlite في الذاكرة. جرّب رنا وعمر في تبويبين. نور حساب تجريبي خارج الجلسة. يشغّل `npm test` اختبار HTTP مع قاعدة مؤقتة ويتحقق من العضوية والدعوات والموافقة والمراجعة والحذف. تبقى المعاينة المحلية الأصلية على المنفذ 3000.

## تشغيل التطبيق بتسجيل دخول مُدار

أنشئ قاعدة PostgreSQL مخصصة لهذا التطبيق ومشروع Supabase Auth. فعّل تأكيد البريد، واضبط عنوان الموقع المسموح به في إعدادات Auth. انسخ `.env.example` إلى `.env` محليًا واضبط `APP_ORIGIN` على عنوان HTTPS الذي سيفتحه المستخدمون و`SUPABASE_PUBLISHABLE_KEY` على المفتاح العام للمشروع. استخدم `DATABASE_URL` للاتصال الفعلي و`DIRECT_URL` للمهاجرات إذا كان رابط التطبيق عبر مجمّع اتصالات. استعمل اتصال PostgreSQL مخصصًا للخادم وأبقِ جداول إجابات مَوَدّة خارج أي API عام لقاعدة البيانات.

```sh
npm run migrate
npm run build
npm start
```

يربط Express على `127.0.0.1`. وجّه إليه طلبات عنوان HTTPS المحدد في `APP_ORIGIN` من الوكيل العكسي. يثبت الخادم هوية المستخدم والبريد المؤكّد مع Supabase Auth ويتحقق من العضوية والموافقة قبل إرجاع المقارنة. يحتفظ الحساب المقدم من Supabase بسجل تسجيل الدخول الخاص به عند استخدام «حذف بياناتي» داخل مَوَدّة. هذا الإجراء يمسح إجابات المستخدم وعضويته وملاحظات الحوار المشتركة، ويغلق جلساته ويوقف المشاركة مع إبقاء إجابات الطرف الآخر الخاصة.

## حماية الأسئلة والـAPI عند النشر

للعرض العام انشر مجلد [`public-demo/`](../public-demo/index.html) وحده. يحتوي ثلاث أسئلة افتراضية ويعمل بدون تسجيل دخول أو API. أبقِ `dist/` ومجلد المستودع خارج جذر الملفات العامة. الخادم التجاري يقرأ بنك الأسئلة من `dist/questions.js` وقت التشغيل ويعرض فقط ناتج بناء الواجهة من `commercial/build/client/`.

| الحدّ | السقف الابتدائي |
| --- | --- |
| كل طلبات `/api` من نفس عنوان IP | 360 في الدقيقة |
| البحث عن المدن من نفس العنوان | 90 في الدقيقة |
| تسجيل الدخول في المعاينة المحلية من نفس العنوان | 20 في الدقيقة |
| كل الطلبات الموثّقة للحساب | 90 في الدقيقة، منها 35 طلب كتابة |
| إنشاء الجلسات | 5 للحساب و30 لعنوان IP كل 10 دقائق |
| إنشاء الدعوات وقبولها | 8 للحساب و45 لعنوان IP كل 10 دقائق |
| فتح محاور مختلفة للحساب العادي | 6 خلال آخر 5 دقائق عبر جميع جلساته. إعادة فتح محور من نفس إصدار الاستبيان ضمن الفترة ما بتستهلك فتحة جديدة. |

يرد الخادم بـ`429` و`Retry-After` عند تجاوز الحد. تطبّق الواجهة الانتظار على الطلب المرفوض، وتحدّث شاشة الجلسة كل 15 ثانية وهي ظاهرة. حدود عنوان IP والطلبات العادية لكل عملية خادم. حصة المحاور محفوظة في قاعدة البيانات وتبقى مشتركة بين النسخ المتصلة بها. شغّل `npm run migrate` قبل تشغيل إصدار الخادم الجديد.

### ربط Cloudflare

1. شغّل النسخة المُدارة على مضيفك مع `APP_ORIGIN` مضبوط على النطاق العام. اربط [Cloudflare Tunnel](https://developers.cloudflare.com/fundamentals/security/protect-your-origin-server/) بنفس المضيف ووجّه اسم النطاق إلى `http://127.0.0.1:3001` أو إلى المنفذ المحلي اللي ضبطته. خَلّي منفذ Express محليًا والـTunnel هو المدخل العام.
2. اضبط `MAWADDA_CLOUDFLARE_TUNNEL=1` فقط مع `cloudflared` المحلي. عندها يقرأ التطبيق عنوان العميل من `CF-Connecting-IP` القادم من اتصال محلي. اترك الإعداد فارغًا في المعاينة أو إذا كنت تستخدم وكيلًا مختلفًا.
3. طبّق حماية [DDoS](https://developers.cloudflare.com/ddos-protection/) وقواعد [WAF Rate Limiting](https://developers.cloudflare.com/waf/rate-limiting-rules/) لمسارات `/api/` عند Cloudflare. خلي قواعد الـAPI ترجع رفضًا أو `429` بدل صفحة تحدّي تفاعلية داخل الرد. استثنِ ردود الـAPI الخاصة من التخزين المؤقت.
4. راقب أعداد `429` و`5xx` وزمن الاستجابة من لوحة Cloudflare، واضبط حدود الحافة حسب الاستخدام الفعلي. جرّب طلبات عادية من الويب وأندرويد بعد التفعيل.

### تفعيل CAPTCHA وتأكيد البريد

أنشئ Turnstile widget للنطاق العام واضبط مفتاح الموقع العام في `MAWADDA_TURNSTILE_SITE_KEY`. فعّل حماية Turnstile في Supabase Auth وأدخل المفتاح السرّي هناك فقط. اترك تأكيد البريد مفعّلًا. ترسل الواجهة رمز التحقق إلى Supabase مع التسجيل والدخول، وSupabase هو اللي يتحقق منه. اختبر الدخول والتسجيل على الويب وداخل WebView بعد تفعيل الإعدادات. [إعداد CAPTCHA في Supabase](https://supabase.com/docs/guides/auth/auth-captcha) · [حدود Supabase Auth](https://supabase.com/docs/guides/auth/rate-limits)

## حدود هذه المرحلة

- يعرض كل محور أسئلته العشرة من بنك الأسئلة الأصلي. يحتفظ الخادم بالـ150 سؤالًا تحت معرّف إصدار ثابت، وتحتفظ كل جلسة بإصدارها.
- يظهر الملخّص داخل الجلسة عند الموافقة المتبادلة. المؤشر وصفي وغير سريري، ويعرض حجم العينة. الإجابات الناقصة والمؤجلة خارج الحساب، والإجابة المفتوحة تحتاج اعتماد مراجعة من الطرفين.
- تهيئة Supabase وPostgreSQL الخارجية واختبارهما خطوة تالية قبل إشراك أشخاص حقيقيين.
